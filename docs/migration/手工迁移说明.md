# PaperBell 4.6.1 → 5.0.3：VS Code 手工迁移

本指南只迁个人内容，沿用新版系统。每次一个文件夹，复制后立刻适配和检查。本文件包含完整操作步骤；字段与新版结构的完整说明见附录。

## 1. 准备

1. 在两库之外完整备份旧库，包含隐藏 `.obsidian` 与附件，比较文件清单、大小和哈希。旧库原件保留。
2. 关闭两个库的 Obsidian 窗口。在 VS Code 分别打开旧库和新库窗口，操作前看清路径。只读旧库，只在新版编辑。
3. 准备一个库外记录文件夹，放本步改前副本、迁移表和未迁移名单。新版已有个人资料时先备份；干净可下载的新库整库备份可选。
4. 用复制/粘贴（Ctrl+C、Ctrl+V），不用剪切或默认拖动。不要复制旧 `.obsidian`、旧模板/脚本/索引覆盖新版。
5. 每次完成一个小文件夹，检查通过后再开始下一类；同名文件先比较，不点“全部替换”。

迁移表建议列：旧文件、目标、复制/合并/沿用/暂缓、必要修改、检查结果、改前备份位置。

## 2. 日记与 Inputs

| 复制来源 | 粘贴目标 | 必要修改 |
| --- | --- | --- |
| 00 - 每日日记/DailyNote | 30 - Metadata/DailyNote | 正文与日期名保留，检查活动旧路径和操作链接 |
| 00 - 每日日记/WeeklyNote | 30 - Metadata/WeeklyNote | 有真实周记才复制，核对命名 |
| Inputs/Books | 20 - Inputs/Books | 通常只检查封面、附件 |
| Inputs/Clippings | 20 - Inputs/Clippings | 通常只检查图片 |
| Inputs/Zotero | 20 - Inputs/Zotero | 逐篇追加 keywords，保留 concepts 和原 key |

Links 先跳过，在清单里写源路径、备份位置和“待用户选择”。

Zotero 属性示例：

```yaml
concepts:
  - water
  - to-read
keywords:
  - water
```

已有 keywords 就合并去重，不能写两个同名 YAML 键。不要按 Ctrl+H 全部替换 concepts：项目概念与阅读标记不是同一回事。PDF 是外部资源时原链接先保留，另列待办。

## 3. 学者、机构、概念

**学者**：复制 `Persons/Scholars` 内笔记到 `30 - Metadata/Scholars`。对照新版学者模板，删除旧“最新动态”标题和配套 DataviewJS 区，保留个人信息、研究兴趣及论文列表。每篇确认删除边界，勿用正则删除全库代码块。

**机构**：复制 `Locations/Institutes` 内笔记到 `30 - Metadata/Institutes`。只把属性区标签 `university` 改为 `institute`，保留其他标签和坐标。Places 与 Links 一样列待选。

**概念**：复制 `Cards/Concepts` 内笔记到 `10 - Cards/Concepts`。同名先合并定义和来源；补 `category: concept`、`featured: false`。旧论文嵌入改为 `![[概念反查.base#相关论文]]`，按新版补相关学者与输出视图。

概念卡的“相关想法”脚本保留，将数组改为：

```javascript
let folderChoicePaths = ["30 - Metadata/DailyNote", "20 - Inputs", "50 - Outputs", "40 - Projects"];
```

再对照新版脚本检查空名称过滤。定义不要放进 Cards Wrangler 自动管理区。学者删旧动态查询与概念保留相关想法脚本是不同规则。

## 4. 项目

1. 在 `40 - Projects` 建项目名文件夹，将旧项目复制为 `<项目名>/<项目名>.md`；已有同名主页则比较合并，不保留两份正式主页。
2. 封面放同目录，保留真实扩展名，banner 写库内完整路径。
3. 对照新版项目模板，保留个人资料，补 acronym、project/index、project/缩写 和真实 stage。
4. 将每条 YAML milestones 手动转成正文任务；完成用 `[x]`，未完成用 `[ ]`，每条带 `#milestone #project/缩写`，原日期与额外字段保留。
5. 核对条数、完成数、日期后移除旧活动 milestones 数组；原页已在库外备份。
6. 将旧参与者/时间线脚本替换为新版 Base 页面结构，导航用新版脚本。不要复制旧 Base 文件。

```markdown
## 参与者
![[项目素材反查.base#参与者]]

## 里程碑
- [ ] 完成初稿 #project/MyProject #milestone 📅 2025-10-01

## 资助
![[项目资助.base]]

## 交付物
![[项目交付物.base]]

## 相关素材
![[项目素材反查.base#相关论文]]
```

以上项目名、任务、日期只是语法示例，必须换成真实内容。新版示例进度不能覆盖个人进度。

## 5. Drafts 和 Longform

普通草稿复制到 `50 - Outputs/Drafts`，封面等系统路径改为新版。

Longform 每个旧项目单独放入 `50 - Outputs/Longform/<项目>`，不覆盖新版 paper-demo。

1. 复制完整项目及必要资源，原件不动。
2. 用 VS Code 资源管理器的重命名操作，将 `Index.md` 改为 `Main Manuscript (Index).md`，`source` 改为 `manuscript`。图片集中到 `figs`，同名先比较。
3. 在索引 YAML 中写 `workflow: PaperBell Manuscript`、`draftTitle: Main Manuscript`、`sceneFolder: manuscript`，模板路径改到 `00 - Obsidian/模板/学术长文本模板 Longform academic template.md`。保留原 scenes 内容与顺序。
4. 参考新版 metadata.json 的结构新建本项目 metadata.json；将旧标题、日期、摘要、关键词、作者、机构和通讯邮箱逐项转入。不要复制示例身份。
5. 按详细说明的字段映射表核对多机构和通讯作者。JSON 的 true/false 不加引号；字符串里的换行使用 `\n`。
6. 已转换的出版作者字段从索引移除，避免维护两套；保留原资料于库外备份。
7. 查找旧索引名、source 路径和 imgs 路径，逐项改活动链接。检查每个场景文件和图片。不要盲改正文代码示例。
8. 在重新打开 Obsidian 后于 Longform 选择新索引；若手工修改 `.obsidian/plugins/longform-paperbell/data.json`，仅改 `selectedDraftVaultPath`，保持关闭库且先备份，不覆盖其他配置。

命名改完不等于能导出。还需 metadata 与新版工作流一致、图片资源路径有效、Bib 可用。导出可以暂缓并记录；不要为“验证”覆盖历史 PDF/Word。Word 使用新版 Word 格式/预设，PDF 使用新版 PDF 流程。

## 6. VS Code 安全查找替换

**小批文件优先用 Ctrl+H（当前文件）**。多个文件才用 Ctrl+Shift+H，展开“要包含的文件”，限制为当前迁入文件或子目录，例如 `10 - Cards/Concepts/某卡.md`。排除 `.obsidian/**`、`00 - Obsidian/**` 和记录目录；专门改某一个必要配置时单独打开，不取消全库保护去批量替换。

关闭正则模式，用完整原文查找；先看匹配列表和上下文，再逐文件替换。路径文字出现于教学代码块、历史说明、网络 URL 时，不直接替换。

| 当前文件中的查找 | 替换为 | 限制 |
| --- | --- | --- |
| `![[概念检索论文.base]]` | `![[概念反查.base#相关论文]]` | 仅迁入概念卡 |
| `sceneTemplate: 40 - Obsidian/模板/` | `sceneTemplate: 00 - Obsidian/模板/` | 仅迁入 Longform 索引 |
| `banner: 40 - Obsidian/img/` | `banner: 00 - Obsidian/img/` | 未另迁项目封面时，目标图必须存在 |
| `[[Projects/ABSESpy]]` | `[[40 - Projects/ABSESpy/ABSESpy]]` | 示例；含别名、标题或 .md 的链接分别核对 |

不要全库把 `Inputs/` 替换成 `20 - Inputs/`，它会命中已经正确的 `20 - Inputs/`。不要批量替换 concepts、删除 dataviewjs 或把 university 全文替换成 institute。

VS Code 的重命名不保证自动修复全部 Obsidian wiki 链接和配置路径；必须搜索旧路径复核。只写笔记名的链接在目标唯一时可保留，不必改成完整路径。

## 7. Bib、附件和必要设置

用 VS Code“选择以进行比较/与已选项目比较”（或并排打开）比较两份 Bib。将旧真实条目合并到新版实际使用的 Bib，不整文件覆盖。相同 key 不同内容先列冲突；保留备份后逐条决定。条目多或嵌套复杂时使用支持 BibTeX 的工具/AI 核对，不凭正则随意删块。

按正文真实引用补缺失附件，同名同内容复用。新库缺少的旧脚本或模板不因此自动补入：先看新版功能能否替代，不能确定的列待选。

只有用到时才修改 Zotero 自动导出的目标 Bib、本机 PDF 路径和仍指旧库的活动链接。自动导出在 Zotero 里设置，复制 Bib 不会自动更新该设置。

## 8. 每步检查、回退与交付

- 原正文、批注、日期、成员和章节顺序保留了吗？
- 新路径、Base 视图、附件实际存在吗？YAML/JSON 有无重复键或语法错误？
- 同名内容与 Bib 冲突是否明确处理？
- 新版系统默认文件是否保持？旧库是否仍完整？
- 未迁入、原缺失和未验证项目是否单独记录？

先保存并完成文件检查，再打开 Obsidian 抽查显示；下一批写入前关闭库并记录外部变化。不能只用编辑器没有报错来证明插件正常。

出错时只回退当前步骤，优先恢复库外改前副本；本步新建文件确认没有后续编辑后才撤回。Ctrl+Z 只适合当前未跨会话的小修改，不能代替迁移备份。

最后把 Links、Places、用途不明自定义文件、旧版淘汰功能逐项列出原件和备份位置，让用户决定。Bib、附件和路径未查完之前，不宣称整个迁移完成；暂缓的导出明确写“未验证”。

## 逐项修改操作手册：按最终迁移结果复现

本手册补充“具体怎么改”，适用于详细说明、手工操作和 AI 执行。项目名、库名、日期等示例仅演示语法；先确认实际文件，再替换。先看完整操作顺序，再做替换表。

## 一、每批操作的固定顺序

1. 关闭目标库；确认旧库完整备份已验证。只打开新版库进行修改。
2. 写下本批源文件列表、目标列表和同名冲突；复制即将修改的目标文件到库外本批备份目录。
3. 复制旧内容到目标目录；同名不同内容先比较，不使用“全部覆盖”。
4. 完成这一类要求的字段、目录、Base、脚本和路径适配。
5. 保存所有文件；重新打开检查。逐项比较正文、元数据和文件数，检查实际图片与引用。
6. 记录本步结果和剩余依赖。每一项没有通过就留在本步，不以“复制成功”结束。
7. 可打开 Obsidian 抽查；进入下一批前重新关闭，核对是否被自动归类、自动套模板或手动编辑改变。

## 二、VS Code 批量替换：完整操作

### 2.1 设置工作范围

1. “文件 → 打开文件夹”，打开**新版库根目录**，不要打开两个库的共同父目录。
2. 按 `Ctrl+Shift+H` 打开跨文件替换。若只看见搜索框，展开替换框。展开搜索详情，显示“要包含的文件”和“要排除的文件”。不同语言版本标签可能略有差异。
3. “要包含的文件”先填本批目录，例如 `10 - Cards/Concepts/**/*.md`。本目录若混有新版原始示例，改为本次迁入的明确文件列表（逗号分隔），或逐文件用 `Ctrl+H`；目录范围不等于只会命中迁入文件。
4. “要排除的文件”填 `.obsidian/**,00 - Obsidian/**,**/.git/**`。备份与记录本来就应放库外。如果编辑必要插件设置，单独打开那个 JSON，不把它混入跨文件替换。
5. 普通字符串替换关闭 `.*`（正则）、关闭 `Ab`（全字匹配），需要严格匹配时开启 `Aa`（区分大小写）。下文写“正则开”时才打开 `.*`。
6. 先填查找内容，看结果数量和文件列表；无命中时先检查包含范围、空格、引号与斜杠，不直接扩大到整个磁盘。
7. 填替换内容，展开命中上下文/替换预览。删除不属于本批的结果，逐文件替换；只有所有命中都符合规则时才对这批“全部替换”。
8. 按 `Ctrl+K S` 保存全部。再次查找旧值，检查零命中或剩余是否有保留原因；搜索新值，检查没有重复编号。
9. 与库外改前文件比较。可以在资源管理器右键文件“选择以进行比较”，再右键另一个文件“与已选项目比较”；也可并排打开。确认改动只在计划区域。

### 2.2 包含范围示例

| 本批 | 包含范围（打开的是新库根目录） |
| --- | --- |
| 日记 | `30 - Metadata/DailyNote/**/*.md` |
| 文献 | `20 - Inputs/Zotero/**/*.md` |
| 学者 | `30 - Metadata/Scholars/**/*.md` |
| 机构 | `30 - Metadata/Institutes/**/*.md` |
| 概念 | `10 - Cards/Concepts/**/*.md` |
| 单个项目 | `40 - Projects/ABSESpy/**/*.md` |
| 单个写作项目 | `50 - Outputs/Longform/demo/**/*.md` |

修改前先验证搜索结果确实包含预期文件。含空格的路径直接填在包含栏，不加命令行引号。文件名本身含逗号时不使用逗号分隔文件列表，改用当前文件替换。

## 三、普通完整路径的批量替换表

先做特殊完整路径，再做通用目录前缀。表中内容按原样输入，不包含 Markdown 代码围栏。

### 3.1 高优先级：重命名后的确切路径（正则关）

| 查找 | 替换 | 适用范围与检查 |
| --- | --- | --- |
| `Projects/ABSESpy.md` | `40 - Projects/ABSESpy/ABSESpy.md` | 只处理旧完整链接；先排除原文已含 `40 - ` 的命中 |
| `[[Projects/ABSESpy]]` | `[[40 - Projects/ABSESpy/ABSESpy]]` | 不带扩展名、别名的 wiki 链接；其他形式见下一段 |
| `Projects/PaperBell.md` | `40 - Projects/PaperBell/PaperBell.md` | 目标唯一主页已确定后使用 |
| `[[Projects/PaperBell]]` | `[[40 - Projects/PaperBell/PaperBell]]` | 同上 |
| `Outputs/demo/Index.md` | `50 - Outputs/Longform/demo/Main Manuscript (Index).md` | 先排除已经有 `50 - ` 的命中；正文示例不强制改 |
| `Outputs/demo/source/` | `50 - Outputs/Longform/demo/manuscript/` | 实际章节已移动后才改 |

普通查找会匹配已有新前缀中的子字符串；这些行只有在命中内容确为旧路径时才能替换。希望同时排除新前缀时，用后面的正则方式，不直接“全部替换”。

### 3.2 Wiki 链接的项目主页重定向（正则开）

查找：

```regex
\[\[(?:40 - )?Projects/ABSESpy(?:\.md)?(?=[|#\]])
```

替换：

```text
[[40 - Projects/ABSESpy/ABSESpy
```

替换值直接包含 `[[`，不用捕获组回填。先检查预览，别名和标题后缀由原文保留。

适用示例：

```text
[[Projects/ABSESpy]] → [[40 - Projects/ABSESpy/ABSESpy]]
[[Projects/ABSESpy.md|模型框架]] → [[40 - Projects/ABSESpy/ABSESpy|模型框架]]
[[40 - Projects/ABSESpy#里程碑]] → [[40 - Projects/ABSESpy/ABSESpy#里程碑]]
```

原有 `[[ABSESpy]]` 不需要修改；已是 `[[40 - Projects/ABSESpy/ABSESpy]]` 不会匹配。其他项目分别替换真实项目名；名字含正则符号时需转义，复杂名称优先用普通查找。

### 3.3 通用前缀（正则开，限定迁入 MD）

| 查找正则 | 替换 | 使用条件 |
| --- | --- | --- |
| `00 - 每日日记/DailyNote/` | `30 - Metadata/DailyNote/` | 指向实际迁入日记 |
| `00 - 每日日记/WeeklyNote/` | `30 - Metadata/WeeklyNote/` | 确认真实周记或保存目录 |
| `Persons/Scholars/` | `30 - Metadata/Scholars/` | 实际链接或查询路径 |
| `Locations/Institutes/` | `30 - Metadata/Institutes/` | 同上；Places 不做替换 |
| `(?<!10 - )\bCards/Concepts/` | `10 - Cards/Concepts/` | 排除已有新路径 |
| `(?<!20 - )\bInputs/Books/` | `20 - Inputs/Books/` | Books 笔记实际已迁入 |
| `(?<!20 - )\bInputs/Clippings/` | `20 - Inputs/Clippings/` | Clippings 已迁入 |
| `(?<!20 - )\bInputs/Zotero/` | `20 - Inputs/Zotero/` | Zotero MD 已迁入，不代表 PDF 已迁入 |
| `(?<!50 - Outputs/)\bDrafts/` | `50 - Outputs/Drafts/` | 只用于根目录旧 Drafts 完整路径 |
| `40 - Obsidian/img/` | `00 - Obsidian/img/` | 图片在新位置已存在；项目独立封面另行处理 |
| `40 - Obsidian/附件/` | `00 - Obsidian/附件/` | 确认已补必要附件 |

这些表达式只防特定重复前缀，不是全文语义过滤器。仍可能命中文档例子、网页 URL 或自定义更深层目录，所以必须检查上下文。反斜杠 Windows 路径、URL 编码路径不使用这张表。

不提供全库 `Projects/ → 40 - Projects/`、`Outputs/ → 50 - Outputs/` 的一键规则：项目有嵌套主页、Longform 有重命名，通用替换会遗漏结构变化。Links/Places 暂缓时也不能提前把所有引用改到不存在的新目录。

### 3.4 字段和脚本路径（优先当前文件、正则关）

| 查找 | 替换 | 注意 |
| --- | --- | --- |
| `![[概念检索论文.base]]` | `![[概念反查.base#相关论文]]` | 只替换概念卡嵌入，不修改旧 Base 程序 |
| `sceneTemplate: 40 - Obsidian/模板/` | `sceneTemplate: 00 - Obsidian/模板/` | Longform 索引 |
| `workflow: PaperBell-Standard` | `workflow: PaperBell Manuscript` | metadata.json 已准备好才执行 |
| `sceneFolder: source` | `sceneFolder: manuscript` | source 实际已重命名 |
| `dv.view("40 - Obsidian/脚本/navigation_buttons")` | `dv.view("00 - Obsidian/脚本/navigation_buttons")` | 只保留新版确实存在的导航脚本 |
| `name => line.includes(name)` | `name => name && line.includes(name)` | 仅旧概念相关想法脚本，与新版模板一致时采用 |

概念脚本目录数组直接整行换成新版数组，不分别裸替换字符串 Inputs、Outputs、Projects。机构标签和 YAML 主题字段按后文方法，不用全文匹配。

## 四、URI 与 URL 编码：单独一批

普通路径和编码路径是两套文本，不要混合。迁入日记曾实际出现以下变化：

```text
vault=PaperBell& → vault=PaperBell-v5.0.3&
paperbell%3Ashow-section-view → paperbell-section%3Aopen-paperbell-section
```

第一个替换必须用实际新库名称的 URL 编码值；匹配结尾 `&` 可避免再次修改以旧名开头的新库名。参数位于末尾、含空格或不同编码时逐项检查，不套这个模式。

第二个是已核对的 5.0.3 插件命令对应示例，不是所有版本的通用规则。应核对新版命令再改。Inbox 的 `obsidian-task-progress-bar%3Aswitch-view-inbox` 在该示例中保持，不能把所有旧命令都换掉。

编码链接的 `file=` 参数应先解码看原目标，再用最终完整目标重新编码；空格为 `%20`，斜杠常见 `%2F`。保留 vault、标题、块 ID 与其他参数的语义。不要对整个 URI 重复编码，避免 `%` 变 `%25`。

本机 `file:///Users/.../Zotero/storage/...` 不是库内文件：必须找到实际 Windows PDF 才能改。迁移笔记本身不会导入 Zotero 条目。

## 五、YAML 与正文：不能靠全库替换的部分

### 5.1 文献 concepts 和 keywords

逐篇打开文件顶部第一对 `---` 之间的 frontmatter。只处理文献目录：

```yaml
# 原文件
concepts:
  - modelling
  - memory
  - ⭐⭐
```

改后保留上述所有原值，在同一属性区添加：

```yaml
keywords:
  - modelling
  - memory
```

无明确主题词时 `keywords: []`，已有字段则合并，不能追加第二个 keywords。`to-read`、星标、`corr:2` 等不确定标记保留 concepts。正文、citekey 和块 ID 不动。主题值中含冒号或特殊字符时使用正确 YAML 引号。

### 5.2 学者删除查询的边界

查找 `## 最新动态`，确认紧随其后的 DataviewJS 是旧日记动态查询。选中该标题、其查询围栏和多余空行，删除到查询围栏结束；若后面还有下一节，下一节保留。

不能用 `dataviewjs[\s\S]*` 一类贪婪正则删除：它可能吞掉个人正文或后续代码块。不能仅删除开头围栏留下 JS 正文。删后检查姓名、机构、研究兴趣、`![[论文检索.base]]` 都还在。Dataview 插件不因此卸载。

### 5.3 机构标签

只在 frontmatter 的 tags 下把列表项 `university` 改成 `institute`，无关正文中的英文 university 保留。有效 aliases 原样保留；空占位可清理为 `aliases: []`。坐标不改，地图区未被新版取消且数据合法时保留。

### 5.4 项目里程碑转换核对表

先在库外记录逐条抽取：任务文本、done、date、progress、endDate、其他字段。再生成正文任务。

```yaml
milestones:
  - task: v1 框架搭建
    date: 2023-09-01
    done: true
    progress: 100
    endDate: 2025-12-11
```

```markdown
- [x] v1 框架搭建（旧记录：progress: 100） #project/PaperBell #milestone 🛫 2023-09-01 📅 2025-12-11
```

done 决定复选框，不能只看 progress。有 endDate 时旧 date 是开始日（🛫）、endDate 是截止日（📅）；没有 endDate 时只写 `📅 date`。附注放在标签前，日期保持在行尾。旧项目 status 与里程碑不一致时记录矛盾，不自动替用户判断。所有任务核对后才移除旧 milestones 字段；其他 frontmatter 不随之删除。新版示例多出来的任务不自动算个人任务。

## 六、Longform 完整转换实例

### 6.1 改名与链接执行顺序

1. 复制整个旧写作项目到新 Longform 下自己的独立目录，保留改前副本。
2. `Index.md → Main Manuscript (Index).md`；`source → manuscript`。
3. 将原 imgs 中使用的图片合并进 figs；同名同哈希复用，不同哈希先决定新名，不能直接覆盖。
4. 索引 sceneFolder 改 manuscript，sceneTemplate 改新版路径，保留原 scenes 顺序。各章开头补 `# 章节名`（取 scene_alias），正文标题从 `###` 起的整体上提到从 `##` 起，代码块内的 `#` 行不动；新版工作流不再注入章节标题。
5. 建 metadata.json 并核对作者关系，再将 workflow 改 PaperBell Manuscript。
6. 查旧索引/章节/图片路径，修实际链接。选中新索引或仅修改 selectedDraftVaultPath。
7. 逐个打开场景和图片，确认历史 PDF/Word 没被覆盖，后续导出使用不冲突的输出名。

新版示例稿的章节直接写文件名，例如 `](organizing.png)`：导出器会把项目目录和 `figs/` 加入资源路径。所以图片已在 figs 且原文是裸文件名时不必改；原文写 `](imgs/x.png)` 这类旧子目录时改为 `](x.png)`（或 `](../figs/x.png)`）。图片统一到 figs 后，不应继续指向旧 imgs 目录。

### 6.2 metadata.json 可填写模板

以下为**虚构占位例子**，必须替换为原项目真实信息，不能直接作为用户身份使用：

```json
{
  "title": "原项目标题",
  "publication_date": "2025-10-11",
  "upload_type": "publication",
  "publication_type": "article",
  "description": "原摘要",
  "creators": [
    {"name": "作者甲", "affiliation": "机构一", "email": "author@example.org"},
    {"name": "作者乙", "affiliation": "机构二"}
  ],
  "keywords": ["原关键词"],
  "journal_title": "原目标期刊或用途",
  "_longform": {
    "acronym": "DEMO",
    "csl": "nature",
    "template": "paperbell",
    "lineno": false,
    "figures_at_end": false,
    "author_affiliations": {"作者甲": ["机构一", "机构二"], "作者乙": ["机构二"]},
    "corresponding": ["作者甲"],
    "extra_yaml": "subtitle: 原副标题\ntitlepage: true\nnumbersections: true\nlineno: false\nfigures-at-end: false\n"
  }
}
```

迁移后检查：creators 数量与顺序等于旧 authors；数字机构编号映射成真实名称列表；对应关系没有反转；corresponding 名称与 creators.name 完全一致；邮箱来自原文；日期仍是原日期，不能自动换成迁移当天。

`_longform` 里的 csl、template、lineno、figures_at_end 会在用元数据面板保存时被删除；lineno、figures-at-end 要长期保留就以 extra_yaml 为准。`false` 是 JSON 布尔值，不是字符串 `"false"`。extra_yaml 是一个字符串，里面换行写 `\n`；JSON 不允许尾逗号和注释。使用项目字体覆盖时，追加实际安装字体对应的 CJKmainfont 等 YAML 字段；不要盲抄 Mac 字体或 Windows 字体。

移除旧索引中已转换的 authors、affiliations、abstract 等出版配置，避免维护两套；索引 title 等用于显示的属性可保留。原索引全文备份于库外。只把新使用说明放进新版索引时，确保个人正文也有明确保留去向，不能把所有 Index 正文当可丢弃说明。

### 6.3 检查必要配置而不恢复旧设置

关闭库后单独打开 `.obsidian/plugins/longform-paperbell/data.json`：

```json
"selectedDraftVaultPath": "50 - Outputs/Longform/demo/Main Manuscript (Index).md"
```

只改这个字段到自己的索引；保留 workflows、pandocAssetsFolder、其他项目与用户设置。新版实际存在 PaperBell Manuscript 才能选择它，不能凭名称猜测。如果 GUI 已可用，也可在 Longform 面板选择新项目，不必手改 JSON。

其他通常不需要重设的值，只核对：

| 功能 | 应指向的新版位置或来源 |
| --- | --- |
| 日记 | 30 - Metadata/DailyNote |
| Calendar 周记 | 30 - Metadata/WeeklyNote |
| Templater 模板目录 | 00 - Obsidian/模板 |
| QuickAdd 新建学者/机构 | 对应 30 - Metadata/Scholars、Institutes |
| ZotLit note.literature-folder | 20 - Inputs/Zotero |
| ZotLit template.folder | 00 - Obsidian/模板 |
| Longform pandocAssetsFolder | 00 - Obsidian/pandoc |

ZotLit 的点号键是完整键名，不是嵌套 JSON 对象。值已正确就不写文件。完整插件配置不能用旧版替换。

## 七、剩余旧路径扫描与解释

只做搜索，不直接替换。开启正则，在迁入文件范围搜索：

# 附录：字段、结构与检查规则

## 1. 目标与边界

先备份旧库，以新版库为基础，逐文件夹复制个人笔记，再按新版模板、字段和目录结构适配。旧库原件始终保留，不剪切、不删除。

本说明是可复用的方法，不是某一份库已经迁移完成的证明。目录和模板以实际新版为准；数量、个人路径、缺失资源和实测结果写在库外迁移记录中。

| 内容 | 默认处理 |
| --- | --- |
| 个人 Markdown 笔记 | 复制到新版对应目录，适配属性、引用和页面结构 |
| Bib 文献条目 | 单独合并，保留真实条目，核对引用键冲突 |
| 笔记实际使用的图片、附件、研究数据 | 新版缺少时补入；相同文件复用；冲突先比较 |
| 插件、脚本、模板、Base 索引、导出预设、Obsidian 配置 | 用新版默认，不恢复旧版整套配置 |
| 自定义或新版无对应类别的文件、淘汰功能 | 先留旧库，列入未迁移清单，最终由用户选择 |
| 历史导出文件 | 有保留价值时原样带入并标记历史产物，不覆盖新导出 |

“主要迁移 MD”不等于丢弃正文必需附件；也不意味着旧库所有 MD 都要复制。旧系统模板、旧手册和旧功能页面即使是 MD，也优先由新版替代。用户自行添加且用途明确、属于已有类别的个人笔记可以照常迁入；用途不明的先列清单。

## 2. 准备、备份和回退

1. 确认旧库、新库和库外记录目录的实际路径。可直接使用新版库作为目标，不必另建工作副本。
2. **正式迁入前完整备份旧库**，包含隐藏 `.obsidian`、附件和子目录。备份放在两库之外。用户应在启动迁移 Skill 前完成；AI 若未找到可验证备份，必须先完成备份，再写新库。
3. 比较备份与旧库的文件清单、大小和 SHA-256。只读盘点可以提前做，但不能代替备份。
4. 新版是可重新下载的干净示例库时，整库备份可选；已有个人数据时应备份。每步即将修改或覆盖的新库文件仍需单独留存改前版本。
5. 写入期间关闭目标库的 Obsidian 窗口，建议旧库也关闭。已确认关闭后无需每个文件重复询问；发生外部变化时重新核对。不要强制终止其他库或擅自关闭同步软件。
6. 建立库外迁移记录：状态、逐文件去向、改前备份、当前新库清单、未迁移清单、未验证项目。

每步按“比较 → 备份目标 → 复制 → 适配 → 检查 → 记录 → 确认下一步”进行。不要先搬完整库再集中修改。检查后若打开 Obsidian 查看，下一步写入前重新关闭并检查外部变动；首次打开还需留意自动归类、自动套模板是否按预期处理迁入文件。

回退只针对当前步：先核对文件仍是该步生成的版本，再恢复改前目标文件、撤回本步新建文件。用户后来编辑过的文件先保留并比较，不能直接覆盖。不要删除旧库或整库回滚来处理一个文件夹的问题。

## 3. 目录对应与执行顺序

下面每一行单独迁移、单独检查；Links 和 Places 默认暂缓，不自动创建目录。

| 旧目录 | 新目录 | 本步关键适配 |
| --- | --- | --- |
| `00 - 每日日记/DailyNote/` | `30 - Metadata/DailyNote/` | 日期、周次、库内链接及操作 URI |
| `00 - 每日日记/WeeklyNote/` | `30 - Metadata/WeeklyNote/` | 有文件才复制，命名按实际配置核对 |
| `Inputs/Books/` | `20 - Inputs/Books/` | 通常直接复制，检查封面和附件 |
| `Inputs/Clippings/` | `20 - Inputs/Clippings/` | 通常直接复制，检查本地与远程图片 |
| `Inputs/Links/` | 待定 | 留旧库，最终由用户决定 |
| `Inputs/Zotero/` | `20 - Inputs/Zotero/` | 保留批注与 key，追加干净的 keywords |
| `Persons/Scholars/` | `30 - Metadata/Scholars/` | 移除旧“最新动态”查询区，采用新版页面 |
| `Locations/Institutes/` | `30 - Metadata/Institutes/` | university 标签改 institute |
| `Locations/Places/` | 待定 | 与 Links 相同，不自动恢复 |
| `Cards/Concepts/` | `10 - Cards/Concepts/` | 新版 Base 引用、相关想法脚本路径 |
| `Projects/<项目>.md` | `40 - Projects/<项目>/<项目>.md` | 项目目录、属性、任务式里程碑、Base 引用 |
| `Drafts/` | `50 - Outputs/Drafts/` | 输出属性和附件路径 |
| `Outputs/<写作项目>/` | `50 - Outputs/Longform/<项目>/` | 新版索引、manuscript、figs、metadata.json、工作流 |

干净的 5.0.3 库里 `30 - Metadata` 下默认只有 `Grants`；`Scholars`、`Institutes`、`DailyNote`、`WeeklyNote` 要到首次使用才创建，迁入时按上表新建即可。新版另有 `20 - Inputs/Movies` 和 `30 - Metadata/Grants`，旧库没有对应内容，保持新版默认。旧库自带的示例稿 `Outputs/demo` 没有个人改动时，新版已有 `paper-demo` 示例替代，可列为“新版替代”；有改动或用户要保留时，按上表作为写作项目迁入（操作手册以它为例）。

普通输出按用途放在 `50 - Outputs`，不是所有输出都属于 Longform。个人目录不能仅凭文件夹名称猜测归属。旧系统手册默认沿用新版手册，有个人修改时单列比较。

## 4. 日记、Inputs 与文献字段

### 日记

保留日期文件名和正文。核对 `date`、`week` 与文件名；原本就有错误时先记录，经用户同意再修，不把历史内容纠错混入迁移。没有相邻日记、周记不代表丢失，不创建虚假的历史笔记。

Calendar、日记、QuickAdd 和 Templater 的新版目录正确就保持。旧 `obsidian://` 链接只有实际需要时才改库名与命令 ID；不能仅替换库名就假定旧插件命令仍存在。

### Books、Clippings

复制笔记到对应目录即可，不重新套模板覆盖正文。保留作者、日期等真实资料；不要根据新版示例补造字段。检查封面和附件是否存在；远程图片未下载不等于本地文件迁移失败。

### Zotero

文件名大小写、`citekey`、`zotero-key`、批注、块 ID、Zotero URI 都保留。新版反查主要读 `keywords`，旧 `concepts` 可能混有主题词、阅读状态、星标及其他标记，因此不能全库简单改名。

默认采用兼容追加方式：保留 `concepts`，把确定的主题词合并到 `keywords`，去重，不自动同步两字段。

```yaml
# 迁移前
concepts:
  - water
  - to-read
  - ⭐⭐
```

```yaml
# 迁移后
concepts:
  - water
  - to-read
  - ⭐⭐
keywords:
  - water
```

项目、输出笔记的 `concepts` 有其他用途，不能一并替换。用户明确要移除旧文献字段时，应另查旧查询依赖和非主题标记的保存去向。

复制文献 MD 不等于导入 Zotero 条目或 PDF。外部 Mac PDF 路径不能猜成 Windows 路径；仅在实际附件存在、位置确认后修改。不同文献共用 citekey 时保留为两篇，不擅自合并或改 key。

## 5. 学者与机构

### 学者

复制到 Scholars，保留姓名、别名、联系方式、机构、研究兴趣及其他个人正文。依照新版模板，删除旧“最新动态”标题及其配套 DataviewJS 查询区，改前原文留在备份。不要删除整页其他内容，也不要泛化成删除所有 DataviewJS：其他旧查询（例如自写的论文列表脚本）即使与新版视图功能重复也保留原样，列入待用户选择。

论文列表采用新版现有视图，例如 `![[论文检索.base]]`。若需要学者参与关键词反查，可从原研究兴趣追加明确的 keywords；不编造关注日期，不猜术语别名。拼写差异影响匹配时列待办。

### 机构

只修改 frontmatter 中实际的机构标签：

```yaml
tags:
  - institute
```

保留其他标签、有效坐标、名称、网址、logo 和正文。原 `university` 改为 `institute`；空别名占位可清理，非空别名保留。`![[学者检索.base]]` 使用新版已有文件。

坐标格式与范围检查不等于地理位置已重新确认。有有效坐标且新版支持的 `mapview` 区可以保留；不为迁移重新定位机构。Places 暂缓。

## 6. 术语与概念卡

复制到 Concepts，先比较同名卡，保留原定义和来源。补新版实际需要的 `category: concept`、`featured: false`；不擅自把个人卡设为精选。

将旧 `![[概念检索论文.base]]` 改为：


## 8. Drafts 与 Longform：完成整套新版适配

普通 Drafts 保留正文和日期，采用新版输出属性、封面路径；没有真实概念关联就不编造 concepts。

Longform 不能只搬文件，也不能只改 workflow。采用新版路线时，在本文件夹步骤内同时完成目录、索引、作者元数据和工作流适配：

```text
50 - Outputs/Longform/<项目>/
├─ Main Manuscript (Index).md
├─ metadata.json
├─ manuscript/
│  └─ 原章节文件.md
├─ figs/
│  └─ 原图片文件
└─ references.bib（存在实际引用条目时）
```

`results.json` 仅在有真实数据占位符时建立，不能填示例数值。回复信、补充材料仅在原项目确有这些内容时适配，不复制新版演示内容来凑目录。原 PDF、DOCX、合成稿如保留，应标明历史产物并避免编译覆盖。

### 索引

将 `Index.md` 改为 `Main Manuscript (Index).md`，`source/` 改为 `manuscript/`，图片集中到 `figs/`。图片同名先比较。章节文件名和 scenes 顺序保持，不把新模板重新套到正文。

```yaml
longform:
  format: scenes
  title: 原项目标题
  draftTitle: Main Manuscript
  workflow: PaperBell Manuscript
  sceneFolder: manuscript
  scenes:
    - 原第一章文件名
    - 原第二章文件名
  sceneTemplate: 00 - Obsidian/模板/学术长文本模板 Longform academic template.md
  ignoredFiles: []
```

旧工作流（PaperBell-Standard）编译时用 `scene_alias` 注入二级章节标题，章节正文从三级标题起；新版 PaperBell Manuscript 没有注入标题的步骤，示例章节自带 `# 引言` 并从二级标题起。迁入章节需在正文开头补 `# <scene_alias；没有则用章节名>`；正文最高一级标题低于二级（如从 `###` 起）时，把正文各级标题整体上提到从 `##` 起，已经从 `##` 起的不动（代码块内以 `#` 开头的行一律不动）。这是格式适配，不改正文文字；逐章预览命中后执行，并在记录里写明。

其他必要索引字段保留；出版作者等资料转入 metadata.json 后不要保留两套活动作者配置。同步更新指向旧索引/章节的链接，以及 Longform 当前选中索引 `selectedDraftVaultPath`。新版工作流本身保持默认。

### 作者与出版信息

| 旧索引字段 | metadata.json 中的字段 |
| --- | --- |
| title | title |
| date | publication_date（日期字符串） |
| abstract | description |
| authors，按原顺序 | creators；姓名原样保留，不猜姓/名拆分 |
| affiliation 数字 + affiliations 表 | 真实机构名称；多机构写 `_longform.author_affiliations` |
| 通讯作者标记及邮箱 | `_longform.corresponding` 中写作者名，creator.email 写邮箱 |
| keywords | keywords |
| target | journal_title |
| acronym、csl、模板选择 | `_longform.acronym`、csl、template |
| lineno、figures-at-end | `_longform.lineno`、figures_at_end，使用 JSON 布尔值 |
| subtitle、titlepage 等额外 YAML | `_longform.extra_yaml` 字符串，保留有效值 |

注意：5.0.3 的元数据编辑面板保存时会删掉 `_longform` 里的 csl、template、lineno、figures_at_end（它们改由 Pandoc 预设管理）。手写进 metadata.json 的这四项在编译时仍会被读取，但只保留到下次用面板保存为止，所以上表里它们的位置只是临时的：lineno、figures-at-end 需要长期保留时写进 `extra_yaml`；模板可在导出步骤的选项里选；csl 被删后导出会回退到默认的 nature，要用其他样式只能在面板保存后重新写回，并列入待验证项。

依据新版 metadata.json 的结构填入原项目真实值，不复制示例作者、机构、邮箱、ORCID。没有的信息留空或省略，不伪造。

核对插件实际生成的 Pandoc YAML，确保作者顺序、机构关系、通讯邮箱正确；特别注意 false 值被预设默认值覆盖的情况，必要时在 extra_yaml 显式保留。字体仅在实际环境有需要时按本机字体在项目元数据中覆盖，不修改整套全局预设。

### 图片、引用与导出

分别核对章节内图片路径和合成稿资源路径。章节的 `../figs/x.png` 能打开，不代表合成稿也一定能导出；需检查新版导出器的 resource-path。代码块中的示例图片、示例路径和示例引用与真正执行的配置分开判断。

静态结构与元数据通过后，仍应区分：插件纯函数检查、命令行导出、Obsidian GUI 编译。三者不能互相冒充。当前 PaperBell Manuscript 走 PDF；Word 需要使用新版支持的 Word 格式或对应预设，不靠改文件扩展名实现。

用户要求暂缓导出时停止运行和环境修复，记录“结构已适配，导出待验证”；不安装工具、不恢复提权、不把历史 PDF 当新验证产物。已发现缺失 citekey 或环境错误原样记录，待用户恢复。

## 9. Bib、附件与必须重新设置的路径

只检查实际必要项目，不重新设置全部插件。

| 项目 | 需要操作的条件 |
| --- | --- |
| Bib | 导入/合并旧真实条目；相同 key 不同内容须核对，不静默覆盖或删除 |
| Zotero / Better BibTeX 自动导出 | 用户实际使用且导出目标仍指旧库；在 Zotero 中调整，不能把复制 bib 当设置完成 |
| 本机 PDF 路径 | 迁入文献实际需要且目标文件可确认存在 |
| 个人附件 | 新版缺少且正文真实引用；同名同内容复用 |
| Longform 当前索引 | 迁入项目重命名后同步选中新路径 |
| 旧库内部链接、URI | 指向迁移文件/命令且仍实际使用，逐条核对 |

Longform 导出找 bib 的顺序：先是插件设置“全局参考文献库”列出的文件（新版默认为空）；再是项目自己的 bib，即设置“参考文献库”指定的文件（默认也为空），没有指定时取项目内从稿件目录向上到项目根找到的 `references.bib` / `mybib.bib`。因此合并进 `00 - Obsidian/mybib.bib` 的条目不会自动用于导出：项目实际引用的条目放进该项目的 `references.bib`；是否把库级 bib 填进全局设置，列为待用户确认，不擅自改设置。

未迁移的旧模板、脚本、导出预设、音乐面板等留旧库，列“新版替代”或“待用户选择”。不得因旧文件存在就恢复它的配置。
