# PaperBell 分步迁移

## 任务边界

以新版库为基础，只迁个人 MD、Bib 和必要附件。旧库只读，复制而不剪切。插件、脚本、模板、Base 索引、导出预设和 Obsidian 配置用新版默认；旧系统文件即使为 MD 也不自动导入。优先适配笔记对新版功能的引用，不恢复旧功能依赖。

用户要求只讨论或只写说明时，不迁移。用户指定的路径、范围与已确认选择优先，不重复询问。没有文件访问权限的聊天环境应解释限制、提供步骤，不声称完成磁盘操作。

## 启动或续接

1. 获取实际旧库、新库、库外记录目录；不硬编码某次测试路径或文件数。
2. 正式迁移前必须有完整旧库备份（包括隐藏文件），核对清单、大小、SHA-256。用户应先备份；未有可靠备份时先完成备份，禁止先写新库。可先只读盘点。
3. 干净可重下载的新库整库备份可选；新库已有个人内容时备份。无论是否整库备份，每步修改已有文件前均保留改前版本。
4. 写入时确认目标库窗口已关闭，避免自动归类或套模板。已确认后不反复询问；外部变动先核对，禁止强制终止应用。
5. 续接读取 state、最近一步、清单和待办，比较源库基线及目标最新清单。遇到用户后续编辑，先保护并比较，不覆盖、不重跑已完成步骤。
6. 阅读 [迁移规则](references/paperbell-rules.md) 中当前类别，并按 [步骤检查](references/step-checks.md) 验证。真实新版模板和工作流优先于示例。

## 具体转换的执行依据

执行字段、路径、URI、项目、Longform 转换前，必须阅读 [逐项操作手册](references/operation-playbook.md) 的对应部分：其中列出可限定批量替换的表达式、必须逐篇处理的语义转换、完整 metadata 模板和检查顺序。批量规则只是候选修改，先预览范围与命中，不全库机械执行。

## 每次一个文件夹

按“说明范围 → 比较 → 改前备份 → 复制与新版适配 → 磁盘复核 → 记录 → 报告”执行。默认顺序：日记/周记、Books、Clippings、Zotero、Scholars、Institutes、Concepts、Projects、Drafts、各 Longform 项目、Bib、必要附件、必要路径、最终核对。Links、Places 暂缓，除非用户明确恢复。

同一步已授权的适配和验证直接完成；完成后等待用户“继续/下一步”再处理另一文件夹。此节源于用户选择的逐步核对方式；状态问题不视为推进授权。必要的跨文件夹依赖列待办。不要先搬完整库再统一适配。

没有对应类别、用途不明的自定义文件和淘汰功能先留旧库，逐项列未迁移清单，最终用户选择。明确属于既有类别的个人笔记正常迁入。缺少目录本身不表示禁止创建，应区分新版预期目录和用户暂缓类别。

## 不可漏掉的适配

- Zotero：保留 concepts，干净主题词追加/合并 keywords；不全库重命名，不把状态星标当主题，不改 key/批注 ID。已有策略继续沿用。
- 学者：删除新版取消的旧“最新动态”查询区，备份原文并保留个人正文；不是删除所有 DataviewJS。
- 机构：frontmatter university → institute，保留有效坐标、资料及兼容地图区。
- 概念：保留定义来源，接新版概念反查 Base，更新仍保留的相关想法脚本路径，不把手写正文放入插件管理区。
- 项目：统一项目名/项目名.md 和同目录封面，唯一 acronym 与项目标签，原 milestones 转正文任务；状态、日期、额外信息保留，采用新版 Base。新示例进度与旧真实资料冲突时先明确取舍。
- Longform：同一步完成新版索引名、manuscript、figs、metadata.json、工作流和所选索引路径；保留章节名/顺序/正文，作者机构邮箱按真实资料映射。不能以复制完成代替格式适配。
- Bib/附件：旧 Bib 的真实条目合并进新版 bib，同 key 冲突不猜；附件只补真实依赖。Longform 导出只认项目内的 bib 或全局设置（见规则第 9 节）。Zotero 自动导出和外部 PDF 路径按实际配置另核对。

用户已选择新版格式，不再询问是否恢复旧工作流。保留旧版路线只在用户明确要求时另行处理。无需迁入旧插件、模板、脚本或预设来填满阶段编号。

## 检查与停止条件

检查文件去向、源库哈希、必要属性类型、正文/批注/里程碑/作者对应、活动链接和资源存在。校验 YAML/JSON 时用环境里已有的解析器，不为此安装工具；没有解析器就逐项人工核对，并在记录里写明用的方法。区分原缺失与迁移新增问题，区分代码示例和实际配置。未找到文件、真实同名冲突或语义不明时，仅暂停依赖该信息的写入，继续当前步独立检查。

导出只在授权且未暂缓时执行。插件纯函数、命令行导出、GUI 编译分别记证据。用户暂缓即停止导出、提权、安装与环境修复；结构可完成、导出待验证。不得用旧 PDF 或配置解析成功宣称实测通过。

## 记录和回退

库外记录 state.json、逐文件计划、源库基线、每步目标清单、改前备份、步骤报告、未迁移名单、待验证项。已有记录沿用格式，不重置历史。

逐文件状态区分：copied/adapted/merged/reused_new/replaced_by_new/deferred/pending。步骤状态区分 planned/running/needs_fix/awaiting_confirmation/accepted/deferred/awaiting_runtime_check。状态词可沿用已有记录，但语义必须明确。

state 至少包含 source_vault、working_vault、record_dir、source_backup、current_step、next_step、steps、choices、latest_working_manifest、deferred_files、pending_runtime_checks。不要预填“已完成”。每个文件记录源、目标、处理方法及前后哈希。

回退先比较改后哈希，只撤回本步仍未被用户编辑的文件；不递归删除旧库，不整库覆盖。最终报告列全部未迁入内容及保留位置，用户暂缓项不自动补迁。

## 可选只读盘点

`python scripts/inventory.py <旧库> <新库> --output <库外新报告.json>`

报告路径不得存在，且必须在两库之外。脚本仅给候选映射，不能把候选目标当复制授权；未知目录、项目/Longform 重命名、附件冲突仍需核对。它不执行备份、迁移、字段转换或导出。

## 收尾与规则维护

每步简报：处理范围、关键前后变化、静态检查结果、尚待验证、下一步。不要让用户阅读全部日志才能判断。

用户授权维护说明/Skill 时，将可复用规则写入技能、实际用户数据留库外记录。修改前备份，更新现有 ZIP 并逐成员核对；不要把本次绝对路径、固定数量或账户信息写成永久条件。
