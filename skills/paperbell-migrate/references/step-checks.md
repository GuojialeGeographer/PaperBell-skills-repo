# 逐文件夹检查与完成条件

这些是检查类别，不要求恢复旧功能。用户已授权当前步后直接完成必要适配；跨类别推进仍按用户逐步确认方式。

| 类别 | 必须核对 |
| --- | --- |
| 准备 | 旧库完整备份与原件清单/大小/哈希一致；目标明确；关闭写入目标窗口；库外记录就绪 |
| 日记/周记 | 正文、文件名保留；日期/周次原异常记录；必要 URI 指向正确库与实际命令 |
| Books/Clippings | 内容完整，封面/图片分类为存在、远程或原缺失；不造属性 |
| Zotero | 文件名、key、块 ID、正文保留；keywords 去重，concepts 未误删；PDF 独立待办 |
| Scholars | 原个人资料保留，只移除指定旧查询区；新版 Base 依赖存在 |
| Institutes | institute 标签、原有效坐标及地图数据；不是重新地理定位 |
| Concepts | 定义来源保留；新版 Base/视图存在；脚本路径正确；真实关键词匹配；管理区不覆盖手写内容 |
| Projects | 独立目录、唯一主页与缩写；新版 Base；任务总数/完成数/日期/额外信息逐条对应；封面可解析 |
| Drafts | 输出字段类型和真实内容；附件路径存在 |
| Longform | 新索引、manuscript、figs、sceneFolder、scenes 和所选索引一致；metadata 作者顺序/机构/邮箱/布尔值往返对应；工作流存在；旧身份示例未混入 |
| Bib | 原条目保留，同 key 冲突显式处理；引用缺失列单；自动导出设置未冒充完成 |
| 附件/路径 | 只补真正依赖；源和目标哈希；没有全库裸替换、重复编号或猜测外部路径 |
| 最终 | 每个旧文件有去向；用户暂缓及新版替代单列；旧库未变；实际运行未测则标待验证 |

## Longform 验证层级

1. 结构与数据：YAML/JSON 可解析，场景文件与顺序正确，作者关系一致，图片在正确资源路径下，正文保留。
2. 纯函数/合成检查：可调用实际插件元数据转换逻辑检查输出，但不称为完整 GUI 编译。
3. 命令行导出：仅获授权时运行，记录环境、命令、退出码、警告和新生成文件，检查输出内容。
4. Obsidian 实测：项目识别、章节编辑、查询显示、实际编译与输出。

用户暂缓导出时，完成第 1 层及已授权的独立检查；后两层保留待验证，停止安装、提权和重试。已有失败日志保留，不把失败改写为通过。

## 未迁移清单

每项写源路径、原件/备份位置、原因、候选目标及后续处理。区分用户暂缓、自定义待选、新版替代、原本缺失和外部资源。Links/Places 不自动创建或补迁。待选文件不计为已迁入。
