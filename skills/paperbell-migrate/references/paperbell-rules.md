# PaperBell 4.6.1 → 5.0.3 详细迁移说明

## 1. 目标与边界

先备份旧库，以新版库为基础，逐文件夹复制个人笔记，再按新版模板、字段和目录结构适配。旧库原件始终保留，不剪切、不删除。

本说明是可复用的方法，不是某一份库已经迁移完成的证明。目录和模板以实际新版为准；数量、个人路径、缺失资源和实测结果写在库外迁移记录中。

| 内容 | 默认处理 |
| --- | --- |
| 个人 Markdown 笔记 | 复制到新版对应目录，适配属性、引用和页面结构 |
| Bib 文献条目 | 单独合并，保留真实条目，核对引用键冲突 |
| 笔记实际使用的图片、附件、研究数据 | 新版缺少时补入；相同文件复用；冲突先比较 |
| 插件、脚本、模板、Base 索引、导出预设、Obsidian 配置 | 用新版默认，不恢复旧版整套配置 |
| 自定义或新版无对应类别的文件、淘汰功能 | 先留旧库，列入未迁移清单，最终由用户选择 |
| 历史导出文件 | 有保留价值时原样带入并标记历史产物，不覆盖新导出 |

“主要迁移 MD”不等于丢弃正文必需附件；也不意味着旧库所有 MD 都要复制。旧系统模板、旧手册和旧功能页面即使是 MD，也优先由新版替代。用户自行添加且用途明确、属于已有类别的个人笔记可以照常迁入；用途不明的先列清单。

## 2. 准备、备份和回退

1. 确认旧库、新库和库外记录目录的实际路径。可直接使用新版库作为目标，不必另建工作副本。
2. **正式迁入前完整备份旧库**，包含隐藏 `.obsidian`、附件和子目录。备份放在两库之外。用户应在启动迁移 Skill 前完成；AI 若未找到可验证备份，必须先完成备份，再写新库。
3. 比较备份与旧库的文件清单、大小和 SHA-256。只读盘点可以提前做，但不能代替备份。
4. 新版是可重新下载的干净示例库时，整库备份可选；已有个人数据时应备份。每步即将修改或覆盖的新库文件仍需单独留存改前版本。
5. 写入期间关闭目标库的 Obsidian 窗口，建议旧库也关闭。已确认关闭后无需每个文件重复询问；发生外部变化时重新核对。不要强制终止其他库或擅自关闭同步软件。
6. 建立库外迁移记录：状态、逐文件去向、改前备份、当前新库清单、未迁移清单、未验证项目。

每步按“比较 → 备份目标 → 复制 → 适配 → 检查 → 记录 → 确认下一步”进行。不要先搬完整库再集中修改。检查后若打开 Obsidian 查看，下一步写入前重新关闭并检查外部变动；首次打开还需留意自动归类、自动套模板是否按预期处理迁入文件。

回退只针对当前步：先核对文件仍是该步生成的版本，再恢复改前目标文件、撤回本步新建文件。用户后来编辑过的文件先保留并比较，不能直接覆盖。不要删除旧库或整库回滚来处理一个文件夹的问题。

## 3. 目录对应与执行顺序

下面每一行单独迁移、单独检查；Links 和 Places 默认暂缓，不自动创建目录。

| 旧目录 | 新目录 | 本步关键适配 |
| --- | --- | --- |
| `00 - 每日日记/DailyNote/` | `30 - Metadata/DailyNote/` | 日期、周次、库内链接及操作 URI |
| `00 - 每日日记/WeeklyNote/` | `30 - Metadata/WeeklyNote/` | 有文件才复制，命名按实际配置核对 |
| `Inputs/Books/` | `20 - Inputs/Books/` | 通常直接复制，检查封面和附件 |
| `Inputs/Clippings/` | `20 - Inputs/Clippings/` | 通常直接复制，检查本地与远程图片 |
| `Inputs/Links/` | 待定 | 留旧库，最终由用户决定 |
| `Inputs/Zotero/` | `20 - Inputs/Zotero/` | 保留批注与 key，追加干净的 keywords |
| `Persons/Scholars/` | `30 - Metadata/Scholars/` | 移除旧“最新动态”查询区，采用新版页面 |
| `Locations/Institutes/` | `30 - Metadata/Institutes/` | university 标签改 institute |
| `Locations/Places/` | 待定 | 与 Links 相同，不自动恢复 |
| `Cards/Concepts/` | `10 - Cards/Concepts/` | 新版 Base 引用、相关想法脚本路径 |
| `Projects/<项目>.md` | `40 - Projects/<项目>/<项目>.md` | 项目目录、属性、任务式里程碑、Base 引用 |
| `Drafts/` | `50 - Outputs/Drafts/` | 输出属性和附件路径 |
| `Outputs/<写作项目>/` | `50 - Outputs/Longform/<项目>/` | 新版索引、manuscript、figs、metadata.json、工作流 |

干净的 5.0.3 库里 `30 - Metadata` 下默认只有 `Grants`；`Scholars`、`Institutes`、`DailyNote`、`WeeklyNote` 要到首次使用才创建，迁入时按上表新建即可。新版另有 `20 - Inputs/Movies` 和 `30 - Metadata/Grants`，旧库没有对应内容，保持新版默认。旧库自带的示例稿 `Outputs/demo` 没有个人改动时，新版已有 `paper-demo` 示例替代，可列为“新版替代”；有改动或用户要保留时，按上表作为写作项目迁入（操作手册以它为例）。

普通输出按用途放在 `50 - Outputs`，不是所有输出都属于 Longform。个人目录不能仅凭文件夹名称猜测归属。旧系统手册默认沿用新版手册，有个人修改时单列比较。

## 4. 日记、Inputs 与文献字段

### 日记

保留日期文件名和正文。核对 `date`、`week` 与文件名；原本就有错误时先记录，经用户同意再修，不把历史内容纠错混入迁移。没有相邻日记、周记不代表丢失，不创建虚假的历史笔记。

Calendar、日记、QuickAdd 和 Templater 的新版目录正确就保持。旧 `obsidian://` 链接只有实际需要时才改库名与命令 ID；不能仅替换库名就假定旧插件命令仍存在。

### Books、Clippings

复制笔记到对应目录即可，不重新套模板覆盖正文。保留作者、日期等真实资料；不要根据新版示例补造字段。检查封面和附件是否存在；远程图片未下载不等于本地文件迁移失败。

### Zotero

文件名大小写、`citekey`、`zotero-key`、批注、块 ID、Zotero URI 都保留。新版反查主要读 `keywords`，旧 `concepts` 可能混有主题词、阅读状态、星标及其他标记，因此不能全库简单改名。

默认采用兼容追加方式：保留 `concepts`，把确定的主题词合并到 `keywords`，去重，不自动同步两字段。

```yaml
# 迁移前
concepts:
  - water
  - to-read
  - ⭐⭐
```

```yaml
# 迁移后
concepts:
  - water
  - to-read
  - ⭐⭐
keywords:
  - water
```

项目、输出笔记的 `concepts` 有其他用途，不能一并替换。用户明确要移除旧文献字段时，应另查旧查询依赖和非主题标记的保存去向。

复制文献 MD 不等于导入 Zotero 条目或 PDF。外部 Mac PDF 路径不能猜成 Windows 路径；仅在实际附件存在、位置确认后修改。不同文献共用 citekey 时保留为两篇，不擅自合并或改 key。

## 5. 学者与机构

### 学者

复制到 Scholars，保留姓名、别名、联系方式、机构、研究兴趣及其他个人正文。依照新版模板，删除旧“最新动态”标题及其配套 DataviewJS 查询区，改前原文留在备份。不要删除整页其他内容，也不要泛化成删除所有 DataviewJS：其他旧查询（例如自写的论文列表脚本）即使与新版视图功能重复也保留原样，列入待用户选择。

论文列表采用新版现有视图，例如 `![[论文检索.base]]`。若需要学者参与关键词反查，可从原研究兴趣追加明确的 keywords；不编造关注日期，不猜术语别名。拼写差异影响匹配时列待办。

### 机构

只修改 frontmatter 中实际的机构标签：

```yaml
tags:
  - institute
```

保留其他标签、有效坐标、名称、网址、logo 和正文。原 `university` 改为 `institute`；空别名占位可清理，非空别名保留。`![[学者检索.base]]` 使用新版已有文件。

坐标格式与范围检查不等于地理位置已重新确认。有有效坐标且新版支持的 `mapview` 区可以保留；不为迁移重新定位机构。Places 暂缓。

## 6. 术语与概念卡

复制到 Concepts，先比较同名卡，保留原定义和来源。补新版实际需要的 `category: concept`、`featured: false`；不擅自把个人卡设为精选。

将旧 `![[概念检索论文.base]]` 改为：

```markdown
![[概念反查.base#相关论文]]
![[概念反查.base#相关学者]]
![[概念反查.base#围绕的输出]]
```

三项分别放在相应标题下。核对真实 Base 文件和视图名，不复制旧 Base 覆盖新版。

新版概念卡仍有“相关想法”DataviewJS，应保留并按新版调整：

```javascript
let folderChoicePaths = ["30 - Metadata/DailyNote", "20 - Inputs", "50 - Outputs", "40 - Projects"];
```

个别新版示例卡仍留着旧数组，以术语模板为准。逐段比较新版脚本的空值过滤等修正，避免空别名误匹配；空别名占位可像机构那样清理，非空别名保留。不能把学者“删除旧查询”的规则套到概念卡。手写定义不要无意包入 Cards Wrangler 的 `%%cw:body%%` 管理区。

检查真实词项匹配，不只看字段存在；某张卡没有相关论文可能确实没有匹配词。不得为了让查询有结果而编造关键词。

## 7. 项目：目录、属性、里程碑、Base 一起适配

```text
40 - Projects/
└─ 项目名/
   ├─ 项目名.md
   └─ cover.png 或 cover.jpg
```

图片使用实际格式，不能只改扩展名。已有同名项目时保留唯一正式主页；比较真实旧项目资料与新版示例。进度冲突必须决定采用哪套，不把新版演示里程碑当成用户成果。

保留原负责人、成员、日期、摘要、网址和导航。按新版补唯一 `acronym` 和 `project/<缩写>` 标签，保留 `project/index`。`status: 进行中` 可映射 `stage: 进行`，`已完成` 可映射 `完成`；矛盾的原状态单独记录，不自行修成一致。项目类型等缺少依据时不编造：新版模板的 `type` 只有 研究/开发/管理，`stage` 只有 探索/进行/追踪/完成，旧 `type: 论文` 这类没有对应值的保留原值并列入待用户选择。写入 `stage` 后旧 `status` 行保留，用户要求时再移除。旧 banner 指向共用的默认图时，复制一份到项目目录作封面并改 banner 路径，不移动共用图；没有 banner 就不造封面。

旧 milestones 数组改为正文任务，逐条保留文本、完成状态和日期：

```yaml
milestones:
  - task: 完成初稿
    date: 2025-10-01
    done: false
```

```markdown
- [ ] 完成初稿 #project/MyProject #milestone 📅 2025-10-01
```

`done: true` 转 `[x]`。旧时间线脚本把 `date` 当开始日、`endDate` 当结束日：只有 `date` 时写 `📅 date`（与新版示例项目一致）；同时有 `endDate` 时写 `🛫 date 📅 endDate`，不要把开始日标成截止日。旧 progress 等额外信息保留为任务附注，附注写在标签和日期之前、日期留在行尾；不把未知字段猜成新含义。转换核对通过后移除旧活动 milestones 数组，旧原文保留在备份，避免两套进度不同步。

页面依照新版项目模板使用：

- `![[项目素材反查.base#参与者]]`
- `![[项目资助.base]]`
- `![[项目交付物.base]]`
- `![[项目素材反查.base#相关论文]]`
- `![[项目检索.base]]`

旧参与者和里程碑时间线脚本由上述结构替代；导航沿用新版 `00 - Obsidian/脚本/navigation_buttons`。旧项目列表 Base 不覆盖新版。重新核对完整路径引用、封面路径和项目缩写唯一性。

## 8. Drafts 与 Longform：完成整套新版适配

普通 Drafts 保留正文和日期，采用新版输出属性、封面路径；没有真实概念关联就不编造 concepts。

Longform 不能只搬文件，也不能只改 workflow。采用新版路线时，在本文件夹步骤内同时完成目录、索引、作者元数据和工作流适配：

```text
50 - Outputs/Longform/<项目>/
├─ Main Manuscript (Index).md
├─ metadata.json
├─ manuscript/
│  └─ 原章节文件.md
├─ figs/
│  └─ 原图片文件
└─ references.bib（存在实际引用条目时）
```

`results.json` 仅在有真实数据占位符时建立，不能填示例数值。回复信、补充材料仅在原项目确有这些内容时适配，不复制新版演示内容来凑目录。原 PDF、DOCX、合成稿如保留，应标明历史产物并避免编译覆盖。

### 索引

将 `Index.md` 改为 `Main Manuscript (Index).md`，`source/` 改为 `manuscript/`，图片集中到 `figs/`。图片同名先比较。章节文件名和 scenes 顺序保持，不把新模板重新套到正文。

```yaml
longform:
  format: scenes
  title: 原项目标题
  draftTitle: Main Manuscript
  workflow: PaperBell Manuscript
  sceneFolder: manuscript
  scenes:
    - 原第一章文件名
    - 原第二章文件名
  sceneTemplate: 00 - Obsidian/模板/学术长文本模板 Longform academic template.md
  ignoredFiles: []
```

旧工作流（PaperBell-Standard）编译时用 `scene_alias` 注入二级章节标题，章节正文从三级标题起；新版 PaperBell Manuscript 没有注入标题的步骤，示例章节自带 `# 引言` 并从二级标题起。迁入章节需在正文开头补 `# <scene_alias；没有则用章节名>`；正文最高一级标题低于二级（如从 `###` 起）时，把正文各级标题整体上提到从 `##` 起，已经从 `##` 起的不动（代码块内以 `#` 开头的行一律不动）。这是格式适配，不改正文文字；逐章预览命中后执行，并在记录里写明。

其他必要索引字段保留；出版作者等资料转入 metadata.json 后不要保留两套活动作者配置。同步更新指向旧索引/章节的链接，以及 Longform 当前选中索引 `selectedDraftVaultPath`。新版工作流本身保持默认。

### 作者与出版信息

| 旧索引字段 | metadata.json 中的字段 |
| --- | --- |
| title | title |
| date | publication_date（日期字符串） |
| abstract | description |
| authors，按原顺序 | creators；姓名原样保留，不猜姓/名拆分 |
| affiliation 数字 + affiliations 表 | 真实机构名称；多机构写 `_longform.author_affiliations` |
| 通讯作者标记及邮箱 | `_longform.corresponding` 中写作者名，creator.email 写邮箱 |
| keywords | keywords |
| target | journal_title |
| acronym、csl、模板选择 | `_longform.acronym`、csl、template |
| lineno、figures-at-end | `_longform.lineno`、figures_at_end，使用 JSON 布尔值 |
| subtitle、titlepage 等额外 YAML | `_longform.extra_yaml` 字符串，保留有效值 |

注意：5.0.3 的元数据编辑面板保存时会删掉 `_longform` 里的 csl、template、lineno、figures_at_end（它们改由 Pandoc 预设管理）。手写进 metadata.json 的这四项在编译时仍会被读取，但只保留到下次用面板保存为止，所以上表里它们的位置只是临时的：lineno、figures-at-end 需要长期保留时写进 `extra_yaml`；模板可在导出步骤的选项里选；csl 被删后导出会回退到默认的 nature，要用其他样式只能在面板保存后重新写回，并列入待验证项。

依据新版 metadata.json 的结构填入原项目真实值，不复制示例作者、机构、邮箱、ORCID。没有的信息留空或省略，不伪造。

核对插件实际生成的 Pandoc YAML，确保作者顺序、机构关系、通讯邮箱正确；特别注意 false 值被预设默认值覆盖的情况，必要时在 extra_yaml 显式保留。字体仅在实际环境有需要时按本机字体在项目元数据中覆盖，不修改整套全局预设。

### 图片、引用与导出

分别核对章节内图片路径和合成稿资源路径。章节的 `../figs/x.png` 能打开，不代表合成稿也一定能导出；需检查新版导出器的 resource-path。代码块中的示例图片、示例路径和示例引用与真正执行的配置分开判断。

静态结构与元数据通过后，仍应区分：插件纯函数检查、命令行导出、Obsidian GUI 编译。三者不能互相冒充。当前 PaperBell Manuscript 走 PDF；Word 需要使用新版支持的 Word 格式或对应预设，不靠改文件扩展名实现。

用户要求暂缓导出时停止运行和环境修复，记录“结构已适配，导出待验证”；不安装工具、不恢复提权、不把历史 PDF 当新验证产物。已发现缺失 citekey 或环境错误原样记录，待用户恢复。

## 9. Bib、附件与必须重新设置的路径

只检查实际必要项目，不重新设置全部插件。

| 项目 | 需要操作的条件 |
| --- | --- |
| Bib | 导入/合并旧真实条目；相同 key 不同内容须核对，不静默覆盖或删除 |
| Zotero / Better BibTeX 自动导出 | 用户实际使用且导出目标仍指旧库；在 Zotero 中调整，不能把复制 bib 当设置完成 |
| 本机 PDF 路径 | 迁入文献实际需要且目标文件可确认存在 |
| 个人附件 | 新版缺少且正文真实引用；同名同内容复用 |
| Longform 当前索引 | 迁入项目重命名后同步选中新路径 |
| 旧库内部链接、URI | 指向迁移文件/命令且仍实际使用，逐条核对 |

Longform 导出找 bib 的顺序：先是插件设置“全局参考文献库”列出的文件（新版默认为空）；再是项目自己的 bib，即设置“参考文献库”指定的文件（默认也为空），没有指定时取项目内从稿件目录向上到项目根找到的 `references.bib` / `mybib.bib`。因此合并进 `00 - Obsidian/mybib.bib` 的条目不会自动用于导出：项目实际引用的条目放进该项目的 `references.bib`；是否把库级 bib 填进全局设置，列为待用户确认，不擅自改设置。

未迁移的旧模板、脚本、导出预设、音乐面板等留旧库，列“新版替代”或“待用户选择”。不得因旧文件存在就恢复它的配置。
